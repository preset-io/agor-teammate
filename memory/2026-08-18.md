### Root-causing (evidence)
Pulled the raw Sentry event JSON (`./scripts/sentry.py issue MANAGER-PYTHON-30W --raw`) and the actual source via `gh api repos/preset-io/manager/contents/...` (no local clone access from this session). `preset/managers/recurly.py::list_account_subscriptions` builds subscription dicts using `next(<genexpr> ... if add_on.add_on.name == RecurlyAddons.SEAT.value)` with no default (3 call sites) — when a subscription genuinely lacks a SEAT add-on, this raises `StopIteration`. That IS already caught: an `except StopIteration:` block converts it to a typed `RecurlySubscriptionMissingSeatAddOn`, and the only caller (`TeamController.get_team_subscriptions`, `preset/controllers/api/team.py`) already catches that type and returns a normal HTTP 400 — never a 500. Confirmed via the raw event JSON that Sentry's own tags mark this `mechanism.type=logging`, `tags.handled=yes`, `tags.level=error` — i.e. this is a **fully handled condition** being captured as a full Sentry error purely because the except block called `logger.exception(...)` (ERROR + traceback), independent of the fact that the exception is caught and converted one frame up. Same log-noise-mislabeling class as SC-115301 (Slack channel-fetch) and SC-115260 (UserNotFoundException), both already shipped by this pipeline.
