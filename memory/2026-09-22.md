**Picked: SUPERSET-PYTHON-FVJ** — https://preset-inc.sentry.io/issues/4840756603/ — `NoAuthorizationError: Missing JWT in cookies or headers`, culprit `Api.time_range`. 6535 events all-time, firstSeen 2024-01-10, **still actively firing today** (lastSeen 2026-09-22T14:30). Old and chronic, but — unlike NA4/ZX7 — confirmed as a **live current-master bug**, not deploy lag.

**Root cause** (confirmed via a real non-mocked repro against current `origin/master`, not guessed — built a full app via `create_app()` and called the decorator directly): `superset/views/error_handling.py::handle_api_exception` is stacked *inside* `superset/views/base.py::api` on several legacy-MVC endpoints (`views/api.py::Api.time_range` and siblings in `views/core.py`, `views/datasource/views.py`, `databases/api.py`, `datasets/api.py`, `dashboards/api.py`, `views/base_api.py`). `api`'s own handler for `NoAuthorizationError` (WARNING log + 401) has existed since 2022-06-03 (commit `f270e49c4b0`) and is correct — but `handle_api_exception` runs closer to the view function and has no arm for `NoAuthorizationError`, only a broad `except Exception` (ERROR log + 500 default). Since `has_access_api`'s permission check lazily touches `current_user`, an unauthenticated request raises `NoAuthorizationError` *inside* `handle_api_exception`'s try block, gets caught by its broad `except Exception` first, and `api`'s correct handler never gets a chance. Repro confirmed: calling a `handle_api_exception`-wrapped function that raises `NoAuthorizationError` returns **500** with an ERROR-level `logger.exception` trace, today, on current master.

**Fix** (delegated, in progress): add `except NoAuthorizationError as ex: logger.warning(...); return json_error_response(str(ex), status=401)` to `handle_api_exception`, before the generic `except Exception` arm — mirrors `api`'s own established precedent, self-contained (no import of `get_error_msg` from `base.py`, which would create a circular import since `base.py` already imports `json_error_response` from `error_handling.py`). Test precedent: `tests/unit_tests/views/test_error_handling.py::TestHandleApiExceptionSSHTunnelError` is the exact right shape to mirror (specific-exception arm, WARNING-not-ERROR + non-500 status, verified via `caplog`).
