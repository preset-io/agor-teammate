**Root cause (verified against `origin/master` clone, not guessed):** `DatabaseRestApi.validate_parameters` (`superset/databases/api.py`) catches a marshmallow `ValidationError` and does `message="\n".join(messages)` over `ex.messages.items()` values. `superset/databases/schemas.py` imports `from flask_babel import lazy_gettext as _` and its `extra_validator` (validates the `extra` field's `metadata_cache_timeout` sub-mapping, among others) raises `ValidationError([_("...")])` — a `LazyString`, not a `str`. `str.join()` requires actual `str` instances per item (isinstance check), so this raises exactly the Sentry event's `TypeError: sequence item 0: expected str instance, LazyString found`, turning an intended 422 validation response into an unhandled 500. Confirmed the exact vulnerable line is unchanged at HEAD (current line ~2082, `"\n".join(messages)`) — the ~25-line offset from the Sentry event's frame (api.py:2055/2057) is ordinary line drift from unrelated commits, not a stale-fix signature (unlike YMD above, where the *logic itself* had changed). Confirmed the other two `except ValidationError` handlers in the same file (`table_metadata`/`table_extra_metadata`, ~lines 1106/1197) use `InvalidPayloadSchemaError(ex)` instead — a different, unaffected code path (stores `error.messages` as-is, no manual join) — so this is isolated to `validate_parameters` only.
