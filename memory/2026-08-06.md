### Picked: `MANAGER-PYTHON-36P` — `AttributeError: 'WorkspaceInternalApiV2' object has no attribute 'session'`
1762 occurrences all-time, 0 users impacted (internal admin API, called by the workspace-upgrade flow to identify hibernated selections), first seen 2025-12-03, still firing daily (last seen 2026-08-05). Culprit `WorkspaceInternalApiV2.get_bulk_status`.

**Root cause** (read the actual repo source before touching anything — cloned `preset-io/manager` to `/tmp/manager-explore`): `get_bulk_status` (`preset/controllers/api/internal/v2/workspace.py:923`) calls `self.session.query(Workspace.id, Workspace.status)`. `WorkspaceInternalApiV2` → `WorkspaceInternalApi` → `PresetApi` → `BaseApi` (Flask-AppBuilder) — grepped every one of these base classes, none define a `session` attribute. `self.session` is the pattern used on **manager** classes (`preset/managers/*.py`, backed by `BaseManager.session` → `self._db.session`), not API controllers — confirmed via `grep -rn "self\.session\b"` across the whole repo, every other hit is inside a `preset/managers/` or `preset/middleware/` file. This endpoint has 500'd on literally every call since it was introduced (no other reference to `self.session` in this file, no pre-existing test for `get_bulk_status`). The file already imports and uses `workspace_manager` extensively elsewhere (lines 182, 211, 234, 257...) — it just wasn't used at this one call site.

**Fix**: `self.session.query(...)` → `workspace_manager.session.query(...)`. One-line, no response-shape change.
