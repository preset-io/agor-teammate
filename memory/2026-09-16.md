**Picked: SUPERSET-PYTHON-1739** — `DetachedInstanceError: Instance <Slice> is not bound to a Session; attribute refresh operation cannot proceed`, culprit MCP tool `get_chart_sql`, 1 event, brand new (firstSeen 2026-09-16T12:04:51Z). Chose this from the `--sort new` sweep specifically because its stack-trace line numbers (`get_chart_sql.py:453/512/167`) look current, not stale — worth prioritizing fresh issues over old high-volume ones after two stale-build dead ends today.

**Root cause (verified against current origin/master, full chain in the delegated session's prompt):** `_handle_chart_sql_request` looks up the chart inside `event_logger.log_context("mcp.get_chart_sql.chart_lookup")`, whose exit fires `DBEventLogger.log()` → `db.session.commit()` (writes an audit-log row) → expires all attributes on the `Slice` instance (SQLAlchemy `expire_on_commit` default). The function then crosses several `await ctx.info/warning(...)` yield points before `_resolve_effective_form_data(chart, ...)` reads `chart.params`, triggering a lazy reload that fails because the MCP per-call session is gone by then.

**This exact bug class is already fixed in sibling MCP tools** — `get_chart_preview.py` (and `generate_chart.py`, several `dashboard/tool/*.py` files) all call `db.session.refresh(chart_or_dashboard)` immediately after the chart/dashboard lookup, with a comment explaining precisely this expire-on-commit-then-detach risk. `chart_utils.py::validate_chart_dataset`'s docstring independently documents the same risk (why it takes `datasource_id` not `chart`). `get_chart_sql.py` is simply the one caller that never got the `db.session.refresh()` fix its siblings did — high-confidence, low-risk, precedent-matching fix, not a guess.

**Fix scoped (delegated, not yet confirmed landed as of this log entry):** add `db.session.refresh(chart)` right after the chart lookup in `get_chart_sql.py` (mirroring get_chart_preview.py's exact comment/pattern), plus a defense-in-depth `except SQLAlchemyError` in the outer `get_chart_sql()` try/except (same as get_chart_preview.py). Explicitly told the implementation session NOT to also fix `delete_chart.py`/`get_chart_data.py`/`update_chart.py`, which have the same theoretical gap (call `find_chart_by_identifier` with no refresh) but aren't the reported issue — flagged as follow-up candidates for a future run instead, to respect one-issue-per-run scope.
