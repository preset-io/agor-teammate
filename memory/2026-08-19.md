### Picked: `SUPERSET-PYTHON-15FN` + `SUPERSET-PYTHON-15FK` (24 events each, brand-new today, 0 users so far but actively firing)

Flagged this morning by the 7am spike-check as a "code-shaped, too-low-volume-to-flag" cluster (`SUPERSET-PYTHON-15FN/15FK/15FM/15FJ`) — picked up the two that share a root cause I could verify precisely.

**Repo**: `apache/superset`, `superset/mcp_service/chart/tool/get_chart_data.py` — the MCP (Model Context Protocol) `get_chart_data` tool, a new-ish feature area (heavily documented, own `CLAUDE.md`/`ARCHITECTURE.md`/`SECURITY.md` under `superset/mcp_service/`) that exposes chart data to AI agents.

**Root cause (verified via evidence, not guessed):**
- Both issues are the *same* underlying exception (`DetachedInstanceError: Instance <Slice at 0x...> is not bound to a Session; attribute refresh operation cannot proceed`), just logged twice per occurrence — once via `await ctx.error(...)` (FastMCP's client-facing error channel, which itself logs at ERROR — that's the "Sending ERROR to client: ..." title on 15FN) and once via the tool's own `logger.error("Error in get_chart_data: %s", e)` (15FK's title). Confirmed by reading the actual source at both log call sites (lines 1006/1014 of `get_chart_data.py`).
- `get_chart_data()` fetches the chart via `find_chart_by_identifier(..., query_options=chart_query_options)`, which only eager-loads `Slice.table → SqlaTable.metrics` (added in #39483 for Excel export). The function is `async def` with many `await ctx.info/debug/report_progress(...)` calls and nested `with event_logger.log_context(...)` blocks whose exit calls `DBEventLogger.log()` → `db.session.bulk_save_objects(...); db.session.commit()` (confirmed in `superset/utils/log.py`). Commits expire all previously-loaded ORM attributes by default; MCP's session lifecycle across async/await boundaries is a known, actively-worked class of bug in this subsystem (multiple merged/closed PRs: #42621, #42629, #43007-closed, #39921, #39483; `superset/mcp_service/auth.py`'s `load_user_with_relationships()` docstring explicitly documents "session detachment... happens in MCP tool-execution contexts"). When the session detaches mid-flow, later attribute access on the already-fetched `chart` raises `DetachedInstanceError`.
- The tool's existing broad `except (SupersetException, CommandException, SQLAlchemyError, KeyError, ValueError, TypeError, AttributeError) as e:` handler already catches this — so the tool doesn't crash, but it returns a confusing internal-session error to the caller instead of the actual chart data. Not a "harmless log noise, working as designed" case like prior 12EZ-style fixes — a genuine functional defect.
- **This exact failure mode was already fixed for the sibling tool `get_chart_preview.py`** in merged PR apache/superset#39921 ("fix(mcp): prevent DetachedInstanceError in get_chart_preview", 2026-05-06): call `db.session.refresh(chart)` immediately after fetch to force all columns to load while the session is still live. `get_chart_data.py` never received the equivalent fix — confirmed via `grep` that it has no `db` import and no `session.refresh` call anywhere.

**Fix** (mirrors #39921 exactly): import `db` alongside `event_logger`; add `db.session.refresh(chart)` right after the chart lookup (guarded on `chart is not None`, inside the existing `with event_logger.log_context(...)` block, before any further commit can happen). Did not touch the existing broad exception handler — it stays as the safety net for genuinely unexpected errors.

**Tests**: new `TestDetachedInstanceError` class in `tests/unit_tests/mcp_service/chart/tool/test_get_chart_data.py` — one test confirming `db.session.refresh` is called with the chart right after lookup (verified this actually catches the regression: fails without the fix, passes with it), one confirming it's *not* called on the not-found path. Three pre-existing tests needed a `db.session` stub (`MagicMock()`) added because they route non-mapped fake chart objects — `MagicMock`/`SimpleNamespace`, not real ORM instances — through the lookup, and `refresh()` raises `UnmappedInstanceError` on those; production charts are real mapped `Slice` objects, so this is a test-only accommodation, not a masking of the real fix.

**Verification**: `uvx ruff@0.9.7 check` and `format --check` clean on both changed files. `pytest tests/unit_tests/mcp_service/chart/tool/test_get_chart_data.py tests/unit_tests/mcp_service/chart/tool/test_get_chart_preview.py` — **143 passed**, 0 failures.
