**Picked: SUPERSET-PYTHON-17S8** — https://preset-inc.sentry.io/issues/7757532673/ — `AttributeError: 'str' object has no attribute 'update'`, culprit `DashboardRestApi.get_datasets`. Brand new (firstSeen 2026-09-27T11:14:42Z), only 1 event so far — picked for being a clean, well-evidenced live bug over forcing a higher-volume infra/customer-noise issue, same precedent as 178D/178E (09-21) and 17F0 (09-23).

**Root cause, verified against current `origin/master@2e13cfa3e4`, not guessed:** `superset/models/slice.py::Slice.form_data` does `form_data = json.loads(self.params)` inside a `try/except Exception` that already handles *unparseable* JSON (falls back to `form_data = {}`, logs "Malformed json in slice's params") — but valid JSON that decodes to a non-dict (e.g. `self.params == '"foo"'`, `'42'`, `'null'`, `'[1,2]'`) parses successfully and skips that except block entirely, so the very next line, `form_data.update({"slice_id": ..., "viz_type": ..., "datasource": ...})`, raises exactly this `AttributeError` for any non-dict result (`'str' object has no attribute 'update'` for a JSON-string value, matching the Sentry event). **Reachability confirmed, not assumed**: `superset/charts/schemas.py` types the Chart Create/Update API's `params` field as a bare `fields.String()` (lines 313/377) with no JSON-object-shape validation, and `superset/commands/chart/create.py::CreateChartCommand.__init__` (lines 53-58) does its own `json.loads(params_str)` and explicitly guards with `isinstance(params, dict)` before using it for a viz_type fallback — proving the codebase already knows `params` can decode to a non-dict, but that guard only skips the fallback; it never rejects or coerces the value before the chart is persisted. **Crash path**: `DashboardRestApi.get_datasets` → `DashboardDAO.get_datasets_for_dashboard` → `Dashboard.datasets_trimmed_for_slices` → `BaseDatasource.data_for_slices`, which calls `slc.form_data` for every slice on the dashboard and treats the result as a dict via `.get(...)` throughout its loop — confirming `Slice.form_data` is the single choke point worth fixing, not each caller.
