**Picked: SUPERSET-PYTHON-ZY6** — https://preset-inc.sentry.io/issues/7291702862/ — `UndefinedTemplateFunctionException: 'ref' is undefined`, 204 events, firstSeen 2026-02-25, lastSeen 2026-09-04, culprit `DatabaseRestApi.validate_sql`.

**Root cause** (read from source, not guessed): `superset/commands/database/validate_sql.py`'s `ValidateSQLCommand.run()` catches `SupersetTemplateException` and logs at `logger.error(..., exc_info=True)` before converting to a clean `ValidatorSQL400Error` (400 to client). `UndefinedTemplateFunctionException` (jinja_context.py:69) is a `SupersetTemplateException` subclass, raised specifically when a user's SQL Lab "Validate" request calls an undefined Jinja *function* (e.g. a dbt-style `ref()` macro Superset doesn't provide) — a user-input mistake, not a system fault. Confirmed this is the established classification elsewhere: `superset/sqllab/query_render.py`'s actual SQL-execution path catches this exact exception and silently falls back to raw SQL, treating it as fully benign. validate_sql.py's ERROR-level full-traceback logging of this one exception type is the sole source of the Sentry noise; the client-facing 400 response is already correct and doesn't need to change.

**Fix**: add a dedicated `except UndefinedTemplateFunctionException` branch (before the generic `SupersetTemplateException` branch — subclass-before-parent ordering) that logs at WARNING without `exc_info`, mirroring the sibling `SupersetSyntaxErrorException` branch's log treatment. Same `ValidatorSQL400Error`/message/error_type as before — zero client-facing behavior change, log-severity-only.
