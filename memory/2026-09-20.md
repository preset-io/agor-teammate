`exec_post_processing` dispatches user-supplied `post_processing` chart options (e.g. `resample`) to `superset/utils/pandas_postprocessing/*.py` operators, which validate some inputs via `InvalidPostProcessingError` (400) but don't wrap the underlying pandas calls. **Empirically verified** (pandas 2.3.3, matches this repo's environment): `resample()`'s `rule`/`method` validation never checks that non-time DataFrame columns are numeric before `.interpolate()` (method="linear") or `.mean()`/`.median()` — a DataFrame with an object-dtype column (e.g. a text dimension alongside numeric metrics, plausible for real chart results) makes these raise a raw `TypeError` (`"Cannot interpolate with all object-dtype columns..."` / `"agg function failed [how->mean,dtype->object]"`), uncaught by `except InvalidPostProcessingError`, propagating through `get_query_result` → SQLA datasource query path → `/api/v1/chart/data` as an opaque 500. High reachability: `ExploreMixin.get_query_result` is the shared post-processing chokepoint for the main dataset connector, used by virtually every chart-data/Explore/dashboard query.
