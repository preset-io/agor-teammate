### Picked: `SUPERSET-PYTHON-WE6` — `SqlaTable.adhoc_column_to_sqla()` mislabels DB errors as `ColumnNotFoundException`

**Root cause** (verified by reading source, not guessed): `adhoc_column_to_sqla()` (`superset/connectors/sqla/models.py`) runs a type-probe query via `get_columns_description()` (`superset/connectors/sqla/utils.py`) when resolving an adhoc column's type. `get_columns_description()` wraps **any** exception during query execution — SSL drops, timeouts, syntax errors, genuine zero-column results — into a generic `SupersetGenericDBErrorException` (`except Exception as ex: raise SupersetGenericDBErrorException(message=str(ex)) from ex`). The caller's `except SupersetGenericDBErrorException as ex: raise ColumnNotFoundException(message=str(ex)) from ex` then blindly relabels **all** of these as `ColumnNotFoundException`, conflating "the column genuinely doesn't exist" (deliberate `raise SupersetGenericDBErrorException("Column not found")` when `col_desc` is empty) with "the DB connection dropped mid-probe."

**Beyond log noise — real correctness impact**: `ColumnNotFoundException` is caught in `superset/models/helpers.py`'s `where_clause` adhoc-filter handling (~line 4024): when raised, the filter is silently dropped from the query (`rejected_adhoc_filters_columns.append(flt_col); continue`) rather than surfacing as a DB error. So a transient SSL/connectivity blip during the type-probe causes a chart's adhoc-column filter to be **silently dropped and misreported as "column not found"** instead of a transient DB error — this is the actual event in Sentry: a `wealthsimple-aws-mpc` workspace chart-data request hit `SSL error: unexpected eof while reading` during the probe, got relabeled, and (per the calling code) had its filter dropped.

**Fix**: only raise `ColumnNotFoundException` for the genuine empty-`col_desc` case; let `SupersetGenericDBErrorException` raised *by* `get_columns_description()` itself (real DB/connectivity errors) propagate unchanged with its original message, matching how DB errors are handled everywhere else in this code path.

**Fix**: `superset/connectors/sqla/models.py` — removed the blanket `try/except SupersetGenericDBErrorException: raise ColumnNotFoundException(...)` wrapper around the whole type-probe; `if not col_desc:` now raises `ColumnNotFoundException` directly, and the now-unused `SupersetGenericDBErrorException` import was removed (confirmed no other reference in the file). Test: new `test_adhoc_column_type_probe_propagates_db_error` in `tests/unit_tests/models/helpers_test.py` mocks `get_columns_description` to raise a DB error and asserts it propagates un-relabeled; existing `test_adhoc_column_type_probe_raises_without_comment_safe_retry_hook` confirms the genuine empty-result → `ColumnNotFoundException` path is unchanged. `pytest -k adhoc_column`: 17 passed. `ruff check` + `ruff format --check`: clean.

### Picked: `superset/key_value/shared_entries.py::get_shared_value()` — migration write never commits

**Root cause** (verified by reading source + reproducing empirically): `get_shared_value()` falls back to legacy hash algorithms (`HASH_ALGORITHM_FALLBACKS`, default `["md5"]`) when a shared value isn't found under the current sha256 namespace, and is designed to migrate the entry to the current-algorithm UUID on a fallback hit via `KeyValueDAO.create_entry(...)` — so future lookups skip md5 entirely. But `KeyValueDAO.create_entry()` (`superset/daos/key_value.py`) only does `db.session.add(entry)`, no commit, and `get_shared_value()` — unlike its siblings `set_shared_value()`/`upsert_shared_value()` in the same file — isn't wrapped in the `@transaction()` decorator that would commit it. The migration write is silently discarded every time; every subsequent call re-triggers the deprecated md5 fallback path forever. Confirmed via a throwaway repro test (`patch("superset.db.session.commit")`, in a scratch checkout before touching the real fix): pre-fix 0 commit calls, post-fix exactly 1.

**Fix** (written, tested, verified — not shipped): one line, add `@transaction()` to `get_shared_value()`. Additive-only. Regression test added to `tests/unit_tests/key_value/test_shared_entries_migration.py` (`test_get_shared_value_commits_migration_to_current_algorithm`) — confirmed fails pre-fix (`AssertionError: Expected 'commit' to have been called once. Called 0 times.`), passes post-fix. Full `tests/unit_tests/key_value/` suite: 45/45 pass (via `/tmp/ss-venv`, the known-working venv from prior runs). `ruff check` + `ruff format --check` (`uvx ruff@0.9.7`): clean on both changed files. `mypy`: zero errors attributable to the changed file (pre-existing project-wide noise only, unrelated).
