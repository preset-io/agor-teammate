**Root cause** (verified against `apache/preset-io/manager` master source via `gh api repos/.../contents/...`, not guessed): `TeamMembershipApi.get_team_membership` (`preset/controllers/api/team.py:1241`) calls `user_manager.resolve_user_team_role(user_id, team_id)` with **no try/except at all**. `UserManager.resolve_user_team_role` (`preset/managers/user.py:1280`) raises `UserNotInTeamException` — a `PresetException` subclass — when the target user has no `TeamMembership` row for that team; proven expected/legitimate by a sibling method in the same manager, `is_team_admin`, which already does `except UserNotInTeamException: return False`. Because `get_team_membership` has no except clause, the exception propagates uncaught through Flask/FAB dispatch to the app's global catch-all (`preset/controllers/errors.py::general_error`, `@app.errorhandler(Exception)`), which does `logger.exception("Failed to process request %s", request)` (exact match to the Sentry-captured message) and returns **HTTP 500 / `ApiError.GENERIC`** — not just log noise, an actual wrong-status-code bug (should be 404). Two sibling endpoints in the *same file* already handle this exception correctly: `team.py:774` (`except UserNotInTeamException: return self.error_404(ApiError.NOT_FOUND)`) and `team.py:1425` (`except UserNotInTeamException: return self.error_404(ApiError.USER_NOT_IN_TEAM)`) — mirrored the latter (more precise error code) for the fix. Same exception class as the two just-shipped/merged sibling fixes (MANAGER-PYTHON-374 #3937 merged 08-31, MANAGER-PYTHON-386 #3940 still open) but neither of those PRs' diffs touch this call site — distinct fingerprint, not a duplicate.
