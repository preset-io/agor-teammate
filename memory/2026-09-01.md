**Sibling precedent, same method**: a few lines below (~450-459), the per-sheet-URL check in the exact same `validate_parameters` method already wraps its risky call in `try/except Exception` and appends a `SupersetError` to the returned `errors` list instead of raising — the line-396 call had zero such handling despite being in the identical function whose entire contract is "collect issues, return as a list, never raise."

**Fix**: wrapped the `json.loads` call in `try/except json.JSONDecodeError`, append `SupersetError(error_type=INVALID_PAYLOAD_FORMAT_ERROR, level=ErrorLevel.ERROR)`, `return errors` early — mirrors the method's existing early-return-on-fatal-error pattern (the "Sheet name is required"/"URL is required" checks). Worth remembering as a standing gotcha for any future `json.loads`/`JSONDecodeError` fix in this codebase — always check whether `superset.utils.json` or stdlib `json` is in scope.

**Regression test**: `test_validate_parameters_malformed_credentials` in `tests/unit_tests/db_engine_specs/test_gsheets.py`, matching house style. Uses `"service_account_info": "{not valid json"` (truthy, so it actually reaches `json.loads` — `""` would be swallowed by the existing `or "{}"` fallback and never trigger the bug).
