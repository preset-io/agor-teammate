The function's own `except (TemplateError, SupersetSyntaxErrorException)` clause at line 1885 exists precisely to catch Jinja errors from that call (message: "Error in jinja expression in fetch values predicate") — but because of the try-boundary placement, it can never actually fire for it. This isn't sibling-file drift, it's an in-function scoping bug: the correct handler is *right there*, just mis-scoped by 3 lines.

**Root cause, verified empirically (not guessed):**
- `jinja2.exceptions.UndefinedError.__mro__` confirmed `TemplateError` subclass (`python3 -c "import jinja2.exceptions as e; print(e.UndefinedError.__mro__)"`).
- Read `BaseTemplateProcessor.process_template` (`superset/jinja_context.py:986-1064`): parse-time errors get wrapped into `SupersetSyntaxErrorException`; at render time, `except UndefinedError` only converts to `UndefinedTemplateFunctionException` when the undefined name looks like a function call — otherwise it's a bare `raise` (re-raises raw `UndefinedError`).
- Confirmed Superset's Jinja env uses `DebugUndefined` (not plain `Undefined`), and per the existing [[project…]]-adjacent lesson that DebugUndefined "degrades some undefined-access patterns to a placeholder string instead of raising" — verified directly against `SandboxedEnvironment(undefined=DebugUndefined)`: plain `{{ foo }}` does NOT raise (renders as placeholder text), but `{{ foo.bar }}` (attribute access on undefined) DOES raise `UndefinedError`, since `Undefined.__getattr__` isn't overridden by `DebugUndefined`. So the repro needs attribute/dot access, not a bare variable reference.
- **Reachability**: `get_fetch_values_predicate` is called from `ExploreMixin.values_for_column`/`_reapply_query_filters` (`superset/models/helpers.py`), reached via `superset/datasource/api.py`'s `DatasourceRestApi` column-values endpoint (`datasource.values_for_column(...)`), whose try/except only catches `KeyError`/`NotImplementedError` — nothing else. `SqlaTable` (the concrete class) inherits `ExploreMixin` but defines its own `get_fetch_values_predicate` directly in `connectors/sqla/models.py`, which wins over the mixin's no-op stub by ordinary class-body precedence — explicitly checked this against the #44172 "patched the wrong class" trap before trusting reachability.
- Uncaught `UndefinedError` falls through to Flask's `@app.errorhandler(Exception)` (`superset/views/error_handling.py`) → generic 500/`GENERIC_BACKEND_ERROR`, instead of `QueryObjectValidationError`'s `status=400` via `@app.errorhandler(SupersetException)`.
- **Repro verified empirically before writing any fix code**: wrote a throwaway pytest (`SqlaTable(...)` with `fetch_values_predicate="{{ foo.bar }} = 1"`, mocked `template_processor.process_template.side_effect = UndefinedError(...)`) against a borrowed `/tmp/ss-venv` (needed `pip install -e ./superset-core` again, same recipe as prior runs) — confirmed raw `jinja2.exceptions.UndefinedError` propagates on unmodified code before touching anything.

Regression test `test_get_fetch_values_predicate_wraps_undefined_error` added to `tests/unit_tests/connectors/sqla/models_test.py`, matching that file's existing `SqlaTable(table_name=..., columns=[], metrics=[], database=mocker.MagicMock())` construction pattern (`test_query_bubbles_errors`).
