Small (fresh, low volume) but a clean, unambiguous code bug, not noise — worth the pick over forcing a marginal high-volume infra issue.

**Root cause** (verified against `preset-io/manager` master source via `gh api`): `POST /api/v1/auth` → `AuthApi.auth` (`preset/controllers/api/auth.py:38`) → `generate_api_jwts` → `ApiKeyManager.auth_api_key` (`preset/managers/api_key.py:193`) → `find_api_key_by_name(name)` (`api_key.py:378`), where `name` is the raw unauthenticated client-supplied POST-body field. `find_api_key_by_name` runs a SQLAlchemy `.filter(ApiKey.name == name).one_or_none()`; when `name` contains a NUL byte, psycopg2 rejects it client-side before the query reaches Postgres, raising a bare `ValueError`. Nothing in the chain catches `ValueError` — `auth()` only catches `ApiKeyAuthFailed`/`ApiKeyFeatureDisabledException` — so it propagates to the global handler as an uncaught 500 instead of the clean 401 this should be (a NUL byte can never match a real key name; real names are `uuid.uuid4()`/`generate_random_str` output). `auth_api_key` already has the exact pattern to mirror one branch up (`if api_key is None: ... self._perform_lag_and_raise_auth_exc(perform_dummy_hash=True)`).

**Fix (delegated)**: wrap only the `find_api_key_by_name(name)` call inside `auth_api_key` in `try/except ValueError`, treating it identically to "not found" (log + `_perform_lag_and_raise_auth_exc(perform_dummy_hash=True)`, preserving the timing-attack mitigation). Scoped explicitly to that one call site — told the session not to touch the other finder methods (`find_api_key_by_title_user`/`_service`/`_id_user`, none reachable pre-auth from attacker input) or `AuthApi.auth`'s except clauses.

**Delegated implementation + full shipping pipeline**: branch `fix-manager-43c-nul-byte-api-auth` (`01a0a074-3720-712f-b080-1e61e047cf9d`) on `preset-io/manager` (repo `7dfad085-9fa4-4610-ba37-5f98f235de46`), `storage_mode: clone`, SRE board. Spawned session `01a0a075-17cd-77c7-8a2c-f7afb7166954` (opus, `enableCallback: true` → this session) with the full root-cause chain, exact fix shape, non-vacuous test spec (assert `ApiKeyAuthFailed` not `ValueError` on a NUL-containing name; regression check for the existing not-found path), the manager test recipe (port 5430, `TABLESPACE=pg_default`, borrowed venv), ruff/mypy, and the complete shipping pipeline (Shortcut Implementing→Reviewing, plain `git commit -m` with no identity-assumption language per the classifier learning, PR with a Tradeoffs section disclosing the 500→401 failure-mode change as a strict improvement, self-review session, SRE board card in `zone-pr-ready`, Minerva review/reviewer-assignment request, branch metadata update).
