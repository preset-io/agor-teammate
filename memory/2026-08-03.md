### Picked: `SUPERSET-PYTHON-B8Y` (73,006 events, `EventTimeoutException`) + `SUPERSET-PYTHON-B8X` (1,306 events, "Timed out waiting for ack for event id"), both at culprit `multi_tenant.send_cloud_event`, 0 users impacted.

**Repo**: `preset-io/superset-shell` (not apache/superset or manager — first time this pipeline has picked a Sentry issue rooted in superset-shell's `preset/` package). Confirmed the exact file/line via `gh search code` against the repo before cloning.

**Root cause (verified via evidence)**:
- `preset/tasks.py`'s `multi_tenant.send_cloud_event` celery task (`autoretry_for=(Exception,)`, `max_retries=13`, exponential backoff to 1h — so up to 14 attempts over ~3h) wraps the broker call in try/except and calls `logger.exception(...)` (ERROR + traceback) on **every** attempt before re-raising for autoretry.
- `preset/app.py::configure_sentry()` wires `LoggingIntegration(level=INFO, event_level=logging.ERROR)` — every one of those ERROR log records becomes a distinct Sentry event. That's the volume driver, not genuine failures.
- Confirmed this manual logging is redundant: `sentry-sdk[celery]==2.33.2` is pinned (`setup.py`), and downloaded+inspected the actual wheel — `CeleryIntegration` is in `_AUTO_ENABLING_INTEGRATIONS` (auto-enables since celery is installed, no override found in `configure_sentry`). Read `sentry_sdk/integrations/celery/__init__.py` from that same wheel: `_capture_exception` explicitly ignores `CELERY_CONTROL_FLOW_EXCEPTIONS` (celery's internal `Retry`, which is what `autoretry_for` raises internally on every in-progress retry attempt) and only captures the exception when celery's retry loop is truly exhausted and re-raises the original exception. So Celery + Sentry's own integration already correctly report only the final genuine failure, automatically — no manual logging needed for that.

### Fix (surgical, one line)
Downgrade `logger.exception("Failed to send cloud event, retrying...")` → `logger.warning(..., exc_info=True)` in `preset/tasks.py`. Traceback still preserved for Datadog debugging; no longer creates a Sentry event per transient auto-retried attempt. `raise` kept unchanged so `autoretry_for` still functions identically. No change to retry count/backoff.
