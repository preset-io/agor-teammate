### Picked: `MANAGER-PYTHON-40C` — `WorkspaceUpgradeManager.get_all_target_ids_for_upgrade()` wrong status-filter sentinel

**Root cause** (verified by reading source): `_get_upgrade_for_update(upgrade_id, expected_states=None)` treats an *explicitly passed* `None` identically to "caller omitted the kwarg" — both fall back to `[WorkspaceUpgradeStatus.STAGED]`. `get_all_target_ids_for_upgrade()` calls it with `expected_states=None` intending existence-check-only (per its own docstring), so any GET to the internal target-ids endpoint for an upgrade that exists but isn't STAGED (SUCCESS/RUNNING/FAILED) incorrectly raised `WorkspaceUpgradeInvalidStatusException`. The file already has the correct pattern elsewhere in the same class — `get_upgrade_stats()` passes `expected_states=[]` (falsy, short-circuits the status guard). Confirmed via the Sentry sample event: upgrade id 3082493, status SUCCESS, expected `[STAGED]`.

**Fix**: one-line, `expected_states=None` → `expected_states=[]`, mirroring `get_upgrade_stats`'s existing pattern exactly. **Test**: no prior coverage existed for this method — added `test_get_all_target_ids_for_non_staged_upgrade` and `test_get_all_target_ids_for_upgrade_not_found` to `tests/preset/managers/test_upgrade_manager.py`. Fail-before/pass-after verified on real Postgres; full `WorkspaceUpgradeManagerTests` class: 129/129 passed. `ruff check` + `ruff format --check`: clean.

**Sentry**: [MANAGER-PYTHON-40C](https://preset-inc.sentry.io/issues/MANAGER-PYTHON-40C) — 409 events since 2026-07-20, 0 users.
