Initially looked like the already-known/fixed boxplot mean/median warning (PR #42004, merged 07-17), but deduping without truncating the message revealed **four distinct variants**: median, mean, max, min.

**Root cause investigation:** Reproduced locally (venv `/tmp/soraya-fix-venv`). `_get_aggregate_funcs` (`superset/utils/pandas_postprocessing/utils.py`) already avoids the warning for the *JSON API* path (client sends `"operator": "median"` as a string, no options) — confirmed via repro, no warning. The mean/median variants in prod are the stale-image pattern (old deployed code predating #42004). But **max/min are a live, currently-reachable bug on `origin/master`**: `boxplot()`'s `MINMAX` whisker branch (the `else` case, not `TUKEY`/`PERCENTILE`) sets `whisker_high = np.max` and `whisker_low = np.min` — bare numpy callables — which flow straight through `_get_aggregate_funcs`'s `if callable(operator): aggfunc = operator` branch, untouched by the `_PANDAS_STRING_AGGREGATORS` string-substitution that only applies to string operators. PR #42004 fixed this exact warning class for mean/median in the same `operators` dict but didn't touch max/min. Confirmed no other caller in the repo passes raw numpy callables into `aggregate()`.

**Fix:** `superset/utils/pandas_postprocessing/boxplot.py` — added `is_minmax = whisker_type == PostProcessingBoxplotWhiskerType.MINMAX`, and in the `operators` dict: `"max": "max" if is_minmax else whisker_high`, `"min": "min" if is_minmax else whisker_low`. `whisker_high`/`whisker_low` variables themselves are untouched (still real callables, used directly in `outliers()` and in the `TUKEY`/`PERCENTILE` branches where they're closures, not eligible for the string form). Zero behavior change — pandas resolves the callable form to the identical aggregation today; only a future pandas version would diverge, per the warning's own text.
