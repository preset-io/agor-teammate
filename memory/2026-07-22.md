### Root cause (verified, not guessed)
- manager pins `splitio_client[redis]==10.0.1`. In `RedisSplitStorage.fetch_many`, `mget` returns nil for flags with no Redis key, then `json.loads(None)` raises TypeError → SDK catches and logs `Could not parse feature flag.` at ERROR, returns None → evaluation falls back to caller default.
- Verified via SDK source diff (downloaded 10.0.1 and 10.6.0 tarballs): **identical code path in 10.6.0 — SDK upgrade would NOT fix**. Unknown matcher types are already handled gracefully in 10.0.1 (default-conditions template), so that's not the cause.
- Sentry breadcrumbs pinpoint current trigger: `MGET 'split_.SPLITIO.split.CHATBOT_CUSTOM_SYSTEM_PROMPT_ENABLED'` immediately before the error → **that flag has no key in Redis / likely doesn't exist in the Split workspace**. Evaluated per-workspace during workspace-list serialization → volume.
- Single-flag `get_treatment` also goes through `fetch_many` (evaluator context builder), so every evaluation of a missing flag logs one ERROR.

### Fix shipped
