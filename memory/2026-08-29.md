### Picked: `MANAGER-PYTHON-386` — `UserNotInTeamException` logged as ERROR in `get_workspace_roles_for_user`

https://preset-inc.sentry.io/issues/7289321663/ — 602 events since firstSeen 2026-02-24, still firing (lastSeen 2026-08-28), 0 tracked users.

**Root cause**: `UserInternalApiV2.get_workspace_roles_for_user` (`preset/controllers/api/internal/v1/user.py`) wraps the role lookup in one broad `except PresetException: logger.exception(...)` → 404. `WorkspaceManager.resolve_user_workspace_role` (`preset/managers/workspace.py`) raises `UserNotInTeamException` (a direct `PresetException` subclass) when the target user has no membership in the workspace — an expected condition, proven by a sibling call site in the same file (`user_has_access_to_workspace`) that already treats it as normal (`except UserNotInTeamException: return False`). Because the API layer's except is broad, every occurrence hit ERROR + full traceback, and manager's `setup_sentry` doesn't override Sentry's default `LoggingIntegration` `event_level`, so each became its own event.

This is the **sibling bug to MANAGER-PYTHON-374** (`UserNotFoundException`, same function, same broad-except pattern, fixed via PR #3937 — still open/unmerged as of this pick). #3937's diff adds only an `except UserNotFoundException` clause and doesn't touch `UserNotInTeamException`, so this issue survives #3937 landing. Fixed by mirroring #3937's exact shape for the new exception type.
