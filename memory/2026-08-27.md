### Picked: `MANAGER-PYTHON-374` — `UserNotFoundException: ''` in `get_workspace_roles_for_user`

https://preset-inc.sentry.io/issues/7184655544/ — 51k+ events since firstSeen 2026-01-13, still firing (recent 14d volume ~332 events), `mechanism.type=logging, handled=true`.

**Root cause** (verified against source): `UserInternalApiV2.get_workspace_roles_for_user` (`preset/controllers/api/internal/v1/user.py`, "Called by deployments (shell)") already catches `PresetException` (parent of `UserNotFoundException`, raised by `preset/security/manager.py::get_user_roles_for_workspace` when `find_user_by_username_or_id` finds no local `User` row) and correctly returns a 404 — this is expected, already-handled behavior (e.g. shell checking a workspace role for a SAML/service identity that hasn't been lazily provisioned into the local `User` table yet, or was since removed). The bug is purely that the except block calls `logger.exception(...)` at ERROR with a traceback; manager's `setup_sentry` (`preset/app.py`) doesn't pass an explicit `LoggingIntegration`, so `sentry_sdk`'s default (`event_level=ERROR`) captures every one of these as a production error — 51k+ of them for a condition that already 404s correctly.

**Sibling precedent**: same shape as apache/superset#42484 ("downgrade Slack channel-fetch auth-error logging to WARNING") — narrow the specific expected-exception case to `logger.warning` (no traceback), keep `logger.exception`/ERROR for any other `PresetException` subtype so real failures on this endpoint stay visible. No HTTP-response/behavior change — log-level only.
