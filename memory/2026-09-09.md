### Found the actual pick via cross-pipeline pattern match
`superset/databases/schemas.py::extra_validator` (the marshmallow `validate=` callable wired to the `extra` field on `DatabasePostSchema`/`DatabasePutSchema`/`DatabaseTestConnectionSchema`/import schemas — grepped `validate=extra_validator`, 5+ wiring sites, all sharing this one function):

```python
extra_ = json.loads(value)   # succeeds for ANY valid JSON, not just objects
...
for key in extra_.get("metadata_params", {}):   # unguarded — AttributeError if extra_ isn't a dict
```

Empirically confirmed (standalone `json.loads(v).get(...)` repro, not guessed): `json.loads('123')`→`123`, `'null'`→`None`, `'[1,2]'`→`[1,2]`, `'true'`→`True` — none have `.get()`, all raise `AttributeError: '<type>' object has no attribute 'get'` on the very next line. **This is the identical bug class to today's MANAGER-PYTHON-43B fix, independently present in apache/superset itself.**

**Reachability confirmed**: marshmallow does not catch non-`ValidationError` exceptions raised inside a field `validate=` callable — they propagate straight out of `schema.load()`. `superset/databases/api.py::post()`/`put()` wrap `self.add_model_schema.load(request.json)` / `self.edit_model_schema.load(request.json)` in `except ValidationError` only, nothing broader. So any authenticated user with database create/edit permission sending `POST /api/v1/database/` or `PUT /api/v1/database/<pk>/` with `{"extra": "123"}` (or any non-dict-JSON string: null/list/bool/plain-string) gets a raw unhandled 500 instead of a proper 422.

**Fix precedent found in the SAME function** (best possible form of the sibling-drift pattern this skill looks for — not even a different file): a few lines below the buggy line, `extra_validator` already has the exact isinstance-guard-then-`ValidationError` shape for a nested field:
```python
if "metadata_cache_timeout" in extra_:
    metadata_cache_timeout = extra_["metadata_cache_timeout"]
    if not isinstance(metadata_cache_timeout, dict):
        raise ValidationError([_("The metadata_cache_timeout must be a mapping from string keys to non-negative integer values.")])
```
Applying the identical guard to the top-level `extra_` value itself, right after the `except json.JSONDecodeError` block and before the `metadata_params` loop, is the fix — one isinstance check, no new exception class needed (`ValidationError` from marshmallow, same as every other check in this function).

Also checked `encrypted_extra`/`masked_encrypted_extra` (`_handle_oauth2()` in `commands/database/update.py` has the same-shaped unguarded `json.loads(...).get("oauth2_client_info", {})`, gated behind an existing-OAuth2-config precondition) — narrower reachability, real but not today's pick; noted below for a future run, explicitly told the delegate not to touch it.
